# 聚會字幕 · Meeting Live Captions

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)](https://deploy.workers.cloudflare.com/?url=https://github.com/timo893131/Meeting-Live-Captions)

給教會聚會使用的即時字幕網頁，第一版以繁體中文／國語為主。

## 開發工作流與 Skills

[AGENTS.md](AGENTS.md) 提供共通規則與任務路由；[完整工作流](docs/workflow.md) 分類 UI/UX、即時房間、資料蒐集／爬取、轉換、ASR／詞彙回測、模型微調及驗證發布。七個 Skills 位於 [.agents/skills](.agents/skills)，按任務載入；模板及資料 schema 可用來保存必要的交接與實驗證據。

目前一般真人語音已獲使用者良好回饋，優先改善閱讀／穩定性並建立量化 baseline，再判斷是否需要模型微調。

## 功能

- **個人模式**：在自己的瀏覽器收音、辨識與顯示字幕。
- **廣播模式**：房主裝置收音，經 WebSocket 分享校正後的字幕。
- **加入房間**：輸入房間代碼及密碼，或直接掃描 QR Code／開啟邀請連結。觀看者不需要麥克風。
- 淺藍色介面、專注閱讀、可調整並記住字級；閱讀歷史字幕時不會被新字幕拉走，可一鍵回到最新。
- 房間／收音狀態分開顯示，斷線最多自動重試五次；同頁籤重新整理可恢復房間，麥克風仍需手動開始。
- 支援的瀏覽器可保持螢幕亮起；手機鎖屏或背景限制仍可能暫停收音。
- 可編輯教會詞彙校正表及下載目前保留的字幕。

## Cloudflare 免費方案部署與試用

已提供 Workers + Static Assets + SQLite Durable Objects 版本。請依 [Cloudflare 部署與試用](docs/cloudflare.md) 將 `main` 匯入 Workers，或在自己的電腦登入 Wrangler 後執行 `npm run deploy`。部署成功後才有可跨裝置試用的 HTTPS 網址；免費方案仍有用量上限。

[架構、輕量模型選擇與訓練流程](docs/architecture-and-speech.md) 說明目前使用的瀏覽器辨識及後續自有模型方案。

## 開發（Node 版本）

使用 Node.js 22 以上（本環境驗證於 Node.js 24）。

```sh
npm ci
npm test
npm run dev
```

正式啟動：`npm start`，預設 port 3000，可透過 `PORT` 調整。無資料庫、無需 API key。此專案無額外編譯步驟。

### 外部裝置與 QR Code

請將服務部署在支援 WebSocket 的 **HTTPS** 網站，並設定 `PUBLIC_URL=https://你的網站網域`；QR Code 會使用這個網址。未設定時僅使用 localhost，其他裝置無法透過該 QR Code 連線。瀏覽器收音需要 HTTPS，localhost 開發為例外。不要把 Node 服務直接當作公開的 HTTP 麥克風網站使用。

Node 版本的房間存於單一 Node 程序記憶體；部署請使用一個實例。重啟會清除房間及字幕，房間最長保留 12 小時。房主離線時會顯示離線狀態；暫時的網路中斷會嘗試重連，房主需重新開始收音。房主／觀看者的房間資料保留於同頁籤 sessionStorage，可在重新整理後恢復尚未結束的房間；不會自動重新開啟麥克風。關閉頁籤後不應依賴恢復，離開聚會前請先結束房間。

已登錄使用者指定的兩個 TWGBR 資源，提供有限量來源檢查工具、robots／權利線索及雜湊記錄。[目前來源狀態與執行方式](docs/twgbr-source-review.md)。真實頁面尚受開發環境網路規則阻擋，不能視為已爬取或可供訓練。

## 教會詞彙調整

語音使用瀏覽器的 `SpeechRecognition`（建議桌面版 Chrome），不是本專案訓練的模型。瀏覽器及語音供應商的支援情況、網路及麥克風品質都會影響辨識效果；台語與混語辨識尚未提供。

設定每行 `辨識結果=正確詞彙`，例如：

```text
耶蘇=耶穌
創世紀=創世記
腓力比=腓立比
以馬內力=以馬內利
```

校正以最長匹配的文字為優先，替換結果不會再次被替換；不是模型訓練或辨識引擎的詞彙提示。相同詞彙的項目僅整理專有名詞，不會改善辨識。對詞彙的替換也可能誤改一般語句，請以實際講道評估，針對特定講員加入常見誤識、姓名、書卷及教會名稱。房主端校正後的文字才廣播，參與者不需要相同詞彙表。

下一階段若需要可量測的教會辨識改善，應收集取得授權的代表性音檔和人工逐字稿，評估字錯誤率及專有名詞正確率，再選擇支援繁中、自訂詞彙提示或微調的語音服務。本版未整合雲端語音 API 或訓練流程。

## 隱私與限制（Node 版本）

Cloudflare 版本為支援休眠會將房間驗證資訊及確定字幕儲存在 Durable Object；結束或到期時應用會刪除。詳見 [Cloudflare 的資料保留](docs/cloudflare.md#cloudflare-版本的資料保留)。

- 本伺服器只接收字幕，不接收音訊；瀏覽器可能將音訊傳至其語音服務，請事先告知參與者並取得同意。
- 每間房只保留最近 200 段字幕於記憶體，個人字幕保留於網頁記憶體，下載同樣只包含保留的內容。
- 詞彙表存在瀏覽器 localStorage。房間密碼採 salted scrypt 驗證，QR Code／邀請連結包含觀看用憑證（網址 fragment），不包含密碼或房主憑證；取得邀請連結的人可直接觀看。
- 房主及有密碼的觀眾可以看到房間最近的字幕，不適合公開分享敏感聚會內容。這不是完整的使用者帳號／審計系統。
- 已加入基礎請求限流、內容大小及房間數量限制；大量公開部署仍需 TLS 反向代理及適當的連線／流量管理。
- 字幕可能有誤，經文與神學用語請人工核對。

## 驗證

`npm test` 涵蓋詞彙最長匹配及不重複替換、房間密碼、房主權限、暫定／確定字幕同步、加入後歷史、QR PNG 與房間結束。實際麥克風辨識需在支援的瀏覽器手動驗證：個人模式收音、確認校正，開廣播房間，讓第二台裝置掃 QR Code 並核對字幕同步，再確認手動輸入房間代碼與密碼也能加入。

### UI 與現場流程回歸

```sh
npm ci
npx playwright install chromium
npm run test:ui
```

若系統已裝 Chromium，可用 `CHROMIUM_PATH=/usr/bin/chromium npm run test:ui`。測試自行啟動本機 Node 服務，涵蓋字幕閱讀、收音事件、權限錯誤、房間加入／恢復、有限重連、長字幕與手機版；語音輸入為模擬事件，不代表真實麥克風或模型準確率。沒有安裝瀏覽器時不要把 UI 測試標為通過。

房間憑證存在同頁籤 sessionStorage，與原本僅在頁面記憶體的行為不同；它不提供跨裝置恢復，也不是帳號系統。共享裝置請結束房間並關閉頁籤，請勿匯出或分享瀏覽器儲存內容。
