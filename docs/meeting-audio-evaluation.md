# 已有聚會錄音：第一批真實回測

使用者已確認目標詞彙，並選擇使用已有且獲准評估的聚會錄音。這項用途是評估，不自動包含訓練或公開音訊／逐字稿。尚未收到實際音檔，沒有真實 CER、模型比較或辨識改善數據。

## 收到檔案後

將錄音放在核准的本機位置。以下是命令格式，檔名僅為示意，不代表環境中已有錄音：

```sh
node scripts/prepare-audio-intake.mjs \
  --root data/raw \
  --audio meeting-a.m4a \
  --audio meeting-b.mp3 \
  --output artifacts/meeting-intake/first-batch
```

工具串流計算 SHA-256，以 ffprobe 讀取原音規格，產生 draft-manifest.jsonl、詞彙範圍副本與 intake-report.json。只接受 root 內的單音軌檔案，不修改原音、下載檔案、上傳、重新取樣或執行 ASR。已存在輸出目錄不覆寫，重複原音不重複匯入；檔名與私人 metadata 留在忽略的 artifacts/。

草稿中的音檔屬性與 hash 來自實際檔案；全長區間只是盤點，尚未按說話分段。rights 保留 pending，session_id／speaker_id／group_id 為 null，split 為 unassigned，reference 為 pending。這是刻意不完整的草稿，**不能通過 manifest checker，也不是可訓練資料**。人工填入實際來源與既有授權／同意依據即可，不需要重新取得同一項已有效的評估授權；不要把檔案 hash 當作場次或講員分組。

## 人工校對與切分

- 先選少量代表性片段做開發驗證，包含一般中文、書卷／人物／地名、屬靈詞、多義詞、章節數字、遠距收音與背景噪音；不要只挑辨識清楚的片段。
- 同場與衍生音檔放同一 split；先留出獨立場次作封存測試。單場資料只能報該場效果；若需評估陌生講員，按講員隔離。
- reference 按實際錄音核對，保留漏讀、口誤與實際數字，不能拿預期經文代替所聽見的話。機器稿只能作草稿。
- 「阿們／阿門」同音，字形偏好尚未確認，不應單憑聲音判定拼寫錯誤；「靈／魂／心」保留語意差異。
- 切分後更新 segment_id、時間界線及人工稿；使用 [manifest checker](audio-manifest-check.md) 查核權利 metadata、原音 hash、時間範圍與 split 洩漏。音檔 hash 的來源 URI 只是本機追溯標記，不能代替原始來源與授權依據。

## 如何跑辨識

目前網站用瀏覽器 SpeechRecognition 接收即時麥克風，沒有「匯入錄音辨識」功能，也沒有自有可微調模型。網站下載的字幕已套用校正，不能直接當原始 ASR。播放喇叭再用麥克風收音會引入聲學差異，不作可比較的檔案 baseline。

收到音檔後，先依時長、噪音及環境資源選擇離線辨識引擎。可先比較多語 Whisper base／small（約 74M／244M 參數，非 English-only .en），搭配 faster-whisper 的 int8 CPU 推論；small 通常需要更多資源，是否改善須實測，不能預設適合所有教會詞彙。模型下載與推論尚未執行，也未選定正式模型。離線結果代表該引擎，不能視為瀏覽器供應商的辨識成績。

每個片段保存 raw ASR、校正後字幕、人工 reference、模型／版本／硬體／參數與耗時，再按固定規則量測 CER 和詞彙位置。已有合成工具僅接受合成開發案例，不能把真人資料改標為 synthetic 塞入；真實評估接入會在音檔與人工稿到位後實作。

## 模型微調的判斷點

先比較基線、引擎可用的詞彙提示、文字校正，定位剩餘錯誤。只有持續的聲學／領域誤識、足夠人工對齊資料、獨立測試集，以及涵蓋訓練的資料權利到位後，才評估 LoRA 微調；這次「獲准評估」不等同「獲准訓練」。TWGBR 仍限來源盤點與技術檢查。
